# PRD 002.5 — Deterministic Signals & Insight Cards

**Status:** Ready · **Implements:** Cursor · **Reviews:** Claude · **Depends on:** PRD 001, 002 (data + API exist)

## 1. Context
The product shows raw metrics (numbers) and a (parked) LLM panel — but the **interpretation**
in between is missing, and it's 100% rule-derivable. `metrics.py` already emits much of it
(`cog_shift` comment, sentiment `drivers`, `buildup`, PCR label, S/R). This PRD formalizes a
**deterministic Signals layer**: rules → ranked, plain-language cards, shown for every snapshot.
No LLM. The LLM (PRD 004) is a thin add-on *on top* of these signals.

**Principle:** whatever can be computed from the data is computed and shown directly; AI is an
add-on, never the path for routine output.

## 2. Goal / Non-goals
**Goal:** `core/signals.py` (pure) turns a `MetricsRow` (+ previous + day context) into a ranked
list of signal cards; the API serves them; PRD 003 renders them as the primary "Insights" panel.
**Non-goals:** no LLM; no new metric math (read existing `metrics` columns); no persistence
required v1 (compute on read).

## 3. Functional requirements
1. **Pure module `core/signals.py`.** Input: `MetricsRow` (current) + optional `prev` MetricsRow
   + optional day-context (open/high/low underlying). Output: `list[Signal]`. No I/O.
2. **`Signal` shape:**
   `{key, category, title, text, direction: bullish|bearish|neutral, strength: 0–3, evidence: {field: value, ...}}`.
   `text` is a short plain-English read; `evidence` cites the exact metric values used.
3. **Signal catalog (v1 — all deterministic):**
   | key | rule (from `metrics` cols) | direction / strength |
   |-----|----------------------------|----------------------|
   | `pcr_bias` | `pcr_oi` >1.1 bull / <0.9 bear / else neutral | by distance from 1.0 |
   | `max_pain_pull` | sign+size of `underlying`−`max_pain`, weighted by low `dte` | toward max pain |
   | `level_proximity` | `underlying` within X% of immediate S/R | neutral, strength by closeness |
   | `oi_buildup` | `buildup` enum | long_buildup=bull, short_buildup=bear, covering/unwinding |
   | `support_migration` | `cog_shift` sign/size | up=bull, down=bear |
   | `expected_move` | `atm_straddle`, `expected_move` vs realized day range | neutral (info) |
   | `iv_skew` | `iv_skew` sign | put-rich=bear lean, call-rich=bull lean |
   | `oi_flow` | `net_pe_oi_change` vs `net_ce_oi_change` | PE↑/CE↓=bull, inverse=bear |
   | `pcr_divergence` | `pcr_oi` vs `pcr_volume` disagree | neutral (caution flag) |
   | `overall_read` | `sentiment_score`/`sentiment_label` + `drivers` | from score |
   Thresholds live in module constants (tunable); reuse `metrics.py` comment strings where they exist.

   **Exact thresholds (module constants, v1):**
   - `pcr_bias`: `pcr_oi` >1.10 bullish / <0.90 bearish; strength by |pcr−1|: >0.30→3, >0.15→2, else 1.
   - `max_pain_pull`: d=`underlying`−`max_pain`; |d|/u <0.1%→neutral ("pinned"); else u>mp→bearish, u<mp→bullish; strength by |d|/u (>1%→2 else 1), **+1 if `dte`≤1** (cap 3).
   - `level_proximity`: p=|u−level|/u, only if <0.8%; <0.15%→3, <0.4%→2, else 1; resistance→bearish-lean, support→bullish-lean.
   - `oi_buildup`: long_buildup→bull/2, short_buildup→bear/2, short_covering→bull/1, long_unwinding→bear/1, neutral/null→omit.
   - `support_migration`: `cog_shift` >0 bull / <0 bear; |shift|>30→3, >10→2, >2→1, else omit.
   - `oi_flow`: pe>0&ce<0→bull/3; pe<0&ce>0→bear/3; both>0→larger side/2; both<0→/1; else neutral.
   - `iv_skew`: >0 put-rich (bearish-lean) / <0 call-rich (bullish-lean); |skew|>2→2 else 1.
   - `pcr_divergence`: sign(`pcr_oi`−1) ≠ sign(`pcr_volume`−1) → neutral/1.
   - `overall_read`: strength by |`sentiment_score`|: ≥60→3, ≥25→2, else 1.
   - Ranking: cap **top 6** (config); category priority `[bias, levels, flow, structure, volatility]`.
   - `Signal.evidence` must contain only real metric values used (auditable; never derived/invented).
4. **Ranking.** Sort by `strength` desc, then category priority; cap to top N (config, default 6).
   `overall_read` always first.
5. **API.** Add `GET /instruments/{symbol}/signals?at=latest|<ts>` → computes from the metrics row
   (+ prev) and returns `{time, underlying, overall, signals: [...]}`. Reuse existing metrics queries.
6. **Null-safe.** Missing inputs (null `india_vix`, early `cog_shift`) → omit that signal, never crash.

## 4. File layout
```
core/signals.py                 # Signal dataclass + build_signals(curr, prev=None, day=None) -> list[Signal]
apps/api/routers/signals.py     # GET /instruments/{symbol}/signals
apps/api/models.py              # + Signal, SignalsResponse pydantic models
tests/test_signals.py           # rule tests against real metrics rows (happy + null/edge)
```
`build_signals` is the single entry point. Persistence (a `signals jsonb` column or table) is
**out of scope v1** — add only when alerting/history is needed.

## 5. Acceptance criteria
- [ ] `build_signals` is pure, typed, null-safe; reuses `metrics.py` text where available.
- [ ] All v1 catalog signals implemented with tunable thresholds; `overall_read` always present.
- [ ] `GET /signals` returns ranked cards from real data; bounded; 404 unknown symbol.
- [ ] Every card's `evidence` contains only real metric values (no derived/invented numbers).
- [ ] Tests cover each rule + a null/sparse case; `ruff` clean.
- [ ] No LLM, no new metric computation, no schema migration.

## 6. Roadmap effect
- **003** renders `/signals` as the main interpretation panel; the LLM slot shrinks to an optional
  "AI summary."
- **004 (LLM)** becomes a genuine add-on: narrative/Q&A *over* these signals, cheap-tier, low priority.
